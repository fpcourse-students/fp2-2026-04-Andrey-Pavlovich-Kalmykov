# ФП 2.0. Домашка 4. Типы данных

Условия задач находятся перед кодом в `src/Level1.hs`, `src/Level2.hs` и `src/Level3.hs`. Общие формы данных и выданные интерфейсы — в `src/Defs.hs`, примеры для чтения и запуска — в `src/Examples.hs`. Теория — глава 4 конспекта: вариантность, неподвижная точка функтора, схемы рекурсии и представления через свёртки и развёртки.

## Установка

Нужны GHC 9.10.3, Cabal, `make` и линтер hlint. GHC и Cabal устанавливаются через [ghcup](https://www.haskell.org/ghcup/). После установки выберите версии по умолчанию, по одной команде на строку:

```sh
ghcup install ghc 9.10.3 --set
ghcup install cabal recommended --set
```

На Ubuntu и Debian сначала установите системные зависимости: `sudo apt install build-essential curl libffi-dev libgmp-dev libncurses-dev pkg-config`. Для других систем и Windows следуйте [инструкции ghcup](https://www.haskell.org/ghcup/install/). На Windows `make` доступен в MSYS2, установленном ghcup: `pacman -S make`. Версия компилятора закреплена в `cabal.project`.

Линтер можно установить пакетным менеджером или взять бинарник из [релизов hlint](https://github.com/ndmitchell/hlint/releases); нужна версия не ниже 3.4.1. Его подсказки помогают улучшить код и не влияют на статус задач.

## Уровни задач

* `1.x` — пять обязательных задач: чтение, направления стрелки, катаморфизм, анаморфизм и выражения через `Fix`;
* `2.x` — семь задач для углубления: продолжения, композиция функторов, два варианта `map`, сортировка, список Чёрча, `zipBox` и фильтрация с `Skip`;
* `3.1` — челлендж: компиляция выражений в байткод и трасса стековой машины.

Список задач — в `TASKS`. Статусы: DONE — все проверки прошли; PARTIAL — прошла часть; FAILED — ни одна не прошла; TODO — проверки упёрлись в заглушки. Домашка сдана, когда все пять задач уровня 1 имеют статус DONE. Баллов нет. Цвет CI показывает именно закрытие уровня 1; незавершённые уровни 2 и 3 его не блокируют.

Дедлайнов у домашек нет, но закрытый уровень 1 всех домашек — допуск к экзамену. Лучше делать домашку на той же неделе, пока тема свежая.

## Порядок работы

1. Клонируйте свой репозиторий и выполните `make build`. При первой сборке Cabal установит зависимости.
2. Выполняйте задачи в `src/Level*.hs`. `todo "…"` заменяется реализацией; `todoImpl` обозначает место полного инстанса: удалите эту строку и напишите `instance ... where` с нужными ограничениями и методами. В некоторых задачах дан каркас, в других код нужно написать самостоятельно.
3. Запустите `make repl`. Откроется GHCi со всеми уровнями, примерами и выданными типами. После изменений перезагружайте код командой `:r`. Для просмотра типов используйте `:t` и `:kind!`.
4. До запуска примеров выполните предсказания 1.1. В остальных задачах проверяйте решения вручную; например, `from (iota 5)`, `evalExpr emp357`, `showExpr emp357`.
5. Выполните `make check`: линтер, тесты и таблица статусов. Для выбранных задач — `make check ONLY="1.3 1.4"`. Ненулевой код выхода при незакрытом уровне 1 ожидаем; фильтр `ONLY` также оставляет остальные обязательные задачи незапущенными, то есть TODO.
6. Отправьте текущую версию командой `make submit`. Отчёт CI появится в вашем pull request; после исправлений отправьте новую версию той же командой.

Общие формы и преобразования в `Defs` выданы готовыми. Инстансы из задач пишите самостоятельно, без `deriving`, если условие требует полный инстанс. Для `ExprF` производные `Eq`, `Show`, `Ord`, `Functor` разрешены явно. Адаптеры конструкторов имеют полиморфные сигнатуры: не специализируйте их рекурсивный параметр только на `Expr`.

Зависимости задач: 1.5 использует `cata` из 1.3; 2.3–2.4 используют `cata` и `ana`; 3.1 использует их и форму выражений из 1.5. Пока предшествующая реализация содержит заглушку, зависимая проверка тоже может получить TODO. Чтение, инстансы, Church, Box и фильтрация проверяются независимо от этих решений.

Тесты проверяют поведение и законы на примерах и случайных данных. Требования к способу решения — через указанную схему рекурсии, непосредственно через обработчики или без промежуточных списков — также относятся к задаче и обсуждаются на ревью. Для потоков сравниваются наблюдаемые элементы и, где указано, отдельные шаги, а не скрытые состояния.

## Примеры

`natExample` и `listExample` показывают построение через `In`. Выражения `e3`, `ep35`, `emi35`, `emp357`, `em7p35` используют адаптеры из 1.5. Для 2.6 даны `nats` и `natsFromInterval`: одна последовательность получается из разных скрытых состояний. `brokenFilterS` — намеренно ошибочная функция для 2.7.

Для Church принят порядок аргументов `foldr`: шаг, затем база. У `hylo` сначала коалгебра, затем алгебра, как в конспекте и на слайдах. Диапазон `iota` начинается с 1, как в исходной домашке; в лекционном упражнении диапазон начинается с 0.

## Использование AI

Домашка предназначена для самостоятельного решения. Придумывать решения, проверять гипотезы и разбираться в ошибках полезнее, чем читать готовый код. AI можно использовать как наставника: попросить объяснить тип, предложить наводящий вопрос или помочь понять сообщение компилятора. Не сдавайте код, который не можете объяснить.
